# Практикум темы 3.1. Как машина учится

Два занятия по 2 ак. ч. Датасет обоих занятий — Pima Indians Diabetes (768 пациенток, 8 признаков, целевая переменная Outcome: развился ли диабет). Файл раздаёт преподаватель; источник — в [resources.md](resources.md).

## Занятие 1. Orange: первый конвейер — прогноз диабета («модель за 15 минут»)

**Цель:** собрать первый работающий ML-конвейер и увидеть весь цикл «данные → модель → оценка» до того, как разбирать детали.

**Инструменты.** Вариант А и Б совпадают: Orange Data Mining (десктоп). Понадобится файл `pima_diabetes.csv`.

### Ход занятия

1. Запустите Orange, создайте новый рабочий процесс (`File → New`).
2. Перетащите на холст виджет **File**, двойным щелчком откройте его и укажите файл `pima_diabetes.csv`.
3. В таблице ролей внутри File убедитесь, что столбец `Outcome` имеет роль **target** (целевая переменная), остальные — features. Если нет — измените роль двойным щелчком по колонке «Role».
4. Добавьте виджет **Data Table**, соедините `File → Data Table` (протяните линию от правого края File). Откройте и осмотрите данные: 768 строк, 8 признаков. Что означает каждый столбец — сверьтесь со словарём датасета.
5. Добавьте виджет **Tree** (раздел Model) — это алгоритм «дерево решений».
6. Добавьте виджет **Test and Score** (раздел Evaluate). Соедините: `File → Test and Score` (вход Data) и `Tree → Test and Score` (вход Learner).
7. Откройте Test and Score: слева выберите **Cross validation, 10 folds**. Посмотрите на колонки CA (accuracy), AUC. Запишите значения.
8. Добавьте второй алгоритм — **Logistic Regression** — и тоже соедините с Test and Score. Сравните две строки таблицы: какой алгоритм лучше по AUC?
9. Добавьте виджет **Confusion Matrix** (Evaluate), соедините `Test and Score → Confusion Matrix`. Найдите: сколько больных модель пропустила (ложноотрицательные) и сколько здоровых напрасно «пометила» (ложноположительные).
10. Выберите в Confusion Matrix ячейку ложноотрицательных, добавьте Data Table и посмотрите на этих пациенток: чем они отличаются?
11. Добавьте виджет **ROC Analysis**, соедините с Test and Score, посмотрите на кривые обеих моделей (подробно ROC разберём в теме 3 — сейчас просто зафиксируйте картинку).
12. Сохраните рабочий процесс: `File → Save` → `lesson01_first_pipeline.ows`. Этот файл — часть вашего портфолио.
13. Обсуждение в группе: почему у соседа числа немного другие? (случайное разбиение выборки). Что означает AUC около 0.75 — хорошо это или плохо?

**Ожидаемый артефакт:** файл `lesson01_first_pipeline.ows` с конвейером File → Test and Score (Tree + Logistic Regression) → Confusion Matrix / ROC Analysis и записанными значениями CA и AUC.

### Чек-лист самопроверки

- [ ] Outcome назначен целевой переменной, модель не «предсказывает» возраст.
- [ ] В Test and Score выбрана кросс-валидация, а не «Test on train data».
- [ ] Могу сказать словами, что такое строка и столбец в этой таблице.
- [ ] Могу показать в Confusion Matrix, где ложноотрицательные, и объяснить, чем они опасны клинически.
- [ ] Файл .ows сохранён и открывается заново без ошибок.

### Типичные ошибки

- Соединение Tree напрямую с Confusion Matrix — матрица строится только от Test and Score.
- Режим «Test on train data»: метрики резко «улучшаются» — это экзамен по разобранным билетам (тема 4).
- Не назначена целевая переменная — Test and Score пуст или предсказывает не то.
- Вывод «модель плохая/хорошая» по одной метрике без взгляда на матрицу ошибок.

## Занятие 2. Разведочный анализ и подготовка данных в Orange

**Цель:** научиться смотреть на данные до обучения модели: распределения, пропуски, подозрительные значения, кодирование признаков. Занятие готовит к теме 3.2 «Данные и признаки».

**Инструменты.** Orange Data Mining; тот же `pima_diabetes.csv`.

### Ход занятия

1. Откройте новый рабочий процесс, добавьте **File** с датасетом Pima.
2. Добавьте виджет **Feature Statistics** (раздел Data), соедините с File. Изучите таблицу: среднее, медиана, минимум, максимум, доля пропусков по каждому признаку.
3. Найдите аномалию: минимальное значение Glucose, BloodPressure, BMI, Insulin равно 0. Обсудите: бывает ли глюкоза плазмы 0 ммоль/л у живой пациентки? Это скрытые пропуски, записанные нулём.
4. Добавьте **Distributions**, посмотрите гистограммы Glucose и Insulin: виден «столбик» в нуле. Включите разбивку по Outcome (Split by) — как распределения различаются у больных и здоровых?
5. Добавьте **Box Plot**, сгруппируйте Glucose по Outcome. Сформулируйте клинический вывод одним предложением.
6. Добавьте **Scatter Plot**: оси Glucose и BMI, цвет — Outcome. Есть ли зона, где почти все точки — больные? Кнопка «Find Informative Projections» подскажет самые информативные пары признаков.
7. Превратим нули в честные пропуски: добавьте виджет **Select Columns** и убедитесь в ролях; затем виджет **Edit Domain** не потребуется — используйте **Select Rows** с условием `Glucose равно 0`, чтобы оценить масштаб (сколько таких строк?).
8. Добавьте виджет **Impute** (раздел Data): метод «Average/Most frequent». Обсудите: чем опасна замена средним и почему честнее было бы пометить значения как пропуски на этапе сбора данных. Протокол решения запишите в заметку на холсте (правый клик → Add note).
9. Соберите ветку сравнения: `File → Test and Score` (Logistic Regression) без импутации и `File → Impute → Test and Score` с импутацией. Изменились ли CA и AUC?
10. Кодирование: откройте Feature Statistics и определите, какие признаки числовые, а какие категориальные. В Pima все числовые; обсудите, как выглядела бы переменная «стадия ХБП» (порядковая) и «пол» (категориальная) и что с ними делает виджет Continuize.
11. Сохраните очищенный датасет: виджет **Save Data** → `pima_clean.csv`.
12. Сохраните процесс `lesson02_eda.ows`. Запишите три главные находки о данных в заметку на холсте.
13. Обсуждение: как такие дефекты (нули вместо пропусков) могли возникнуть при сборе данных в клинике? Кто должен был их заметить?

**Ожидаемый артефакт:** `lesson02_eda.ows` с ветками разведочного анализа и импутации + файл `pima_clean.csv` + заметка «протокол находок» (3 пункта: что нашли, что решили, почему).

### Чек-лист самопроверки

- [ ] Могу назвать признаки с «нулями-пропусками» и их долю.
- [ ] Понимаю разницу между «пропуск», «ноль» и «выброс».
- [ ] Зафиксировал(а) в заметке, как обработаны пропуски и почему.
- [ ] Сравнил(а) метрики до и после импутации.
- [ ] Могу объяснить соседу, зачем смотреть на данные до обучения модели.

### Типичные ошибки

- Пропуск разведочного анализа: «сразу к модели» — главная привычка, с которой борется курс.
- Механическая импутация средним без вопроса «почему значение отсутствует» (тяжёлым пациентам инсулин не измеряли — пропуск неслучаен).
- Удаление всех строк с пропусками без оценки, сколько данных и каких пациентов при этом теряется.
- Отсутствие протокола решений: через неделю никто не помнит, что и зачем сделали с данными.
